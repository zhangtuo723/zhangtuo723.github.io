# 个人主页角色制作规格

## 当前状态与目标

已选择保留概念人物，走「专门图生 3D → 造型修整 → 表情绑定 → 网页验证」的制作流程。本文件是交接与验收规格，不是已经完成的角色说明。

当前会话没有可调用的专业 3D 生成服务，也没有已配置的相关服务账号或凭据。这条路线的生产网格尚未真正生成。既有程序化角色只能作为实验记录，不作为本规格的最终角色。接入服务或人工建模后，应记录实际使用的工具、版本、模型授权和输出，不预先承诺服务会自动生成合格拓扑或面部绑定。

最终角色用于公开个人主页，需要在 Three.js 中实时展示自然的中性表情、微笑、眨眼和轻微转头；静态封面也使用同一模型渲染。

## 人物与视觉要求

- 自然、有个性的动画电影风成年东亚男性，年龄观感约 28–35 岁；保持概念图的亲和力与成熟感。
- 无眼镜。五官比例自然，保留脸颊、眼睑、鼻翼、嘴角与下颌的连续形体，避免娃娃脸、过大眼睛、木偶般固定笑容。
- 黑色露额上扫短发，两侧较短，发际线与鬓角自然；用整体体积和明确发流组织头发，避免帽状发壳、等距梳齿或粗面条状发束。
- 深海军蓝夹克，象牙白 T 恤；肩颈比例自然，衣领有真实厚度与褶皱，外套不与脖子、T 恤互穿。
- 保留概念人物的脸型、发型、服装和配色，不在生成时重新换一种画风。皮肤、头发与衣料需有不同的粗糙度和细节尺度。
- 角色是风格化人物，不宣称由本人照片拟合。

## 参考图与生成输入

本目录的参考图由项目方提供，检查实际文件存在后再开始生成：

| 文件 | 用途 |
| --- | --- |
| `concept.png` | 原始人物概念与风格基准 |
| `front.png` | 单人正面参考，优先用于图生 3D 的主输入 |
| `three-quarter.png` | 同一人物的四分之三视角，用于检查体积和修整；仅在工具明确支持对应多视图输入时一并输入 |
| `profile-left-facing.png` | 人物朝画面左侧的侧面设计参考，用于鼻、下颌、耳朵和发型轮廓检查 |
| `back.png` | 后脑、发尾、肩背与夹克背部设计参考 |

这些图由图像生成工具制作，是设计参考，不是从同一三维网格渲染的精确转台，角度、投影、发丝和局部服装细节可能有差异。以 `front.png` 的身份、比例和服装为基准，其他视图用于补充形体。输入前确认人物身份、发型、服装、比例和配色一致；正面图需露出眼睛、双耳区域、颈部与肩部，嘴部自然闭合，无遮挡或夸张表情。若侧视参考与正面有矛盾，先修正参考图，不让生成服务自行猜测不同身份。

已知侧面图的胸袋左右对应不可靠。服装统一采用正面基准：仅人物自身左胸（正面图画面右侧）有一个橙色布标胸袋，右胸不增加同款口袋。侧面图供轮廓参考，不直接用于要求严格相机一致的多视图重建；若服务需要这类输入，先修正左右对应。

默认先用单张 `front.png` 生成静态网格。只有所选模式的官方说明明确支持多视图时，才按其要求分别提供视图；现有参考图不自动等同于该模式所要求的相机角度与姿态。**不要把正面、侧面或四分之三图拼成一张图，交给普通单图模式**，以免生成多个人、多个头或拼接结构。`concept.png` 默认供人工比对，只有工具明确支持独立风格参考时才按其规范使用。

输入图显示半身至大腿中段，目标网页首先使用头肩胸像。不要假定这些图片能可靠生成完整腿脚或标准全身 T/A pose；若后续需要全身行走或自动全身绑定，先补充完整身体和脚部的统一参考。当前验收重点是面部、发型、颈肩与上半身结构。

可用的通用造型描述：

> 按参考图制作单个风格化成年东亚男性半身角色。保留人物身份、自然脸型、露额上扫黑色短发、深海军蓝夹克和象牙白 T 恤。中性闭嘴表情，双眼自然睁开，眼球与眼睑结构清晰，肩颈比例自然，服装层次完整。表面适合 PBR 材质与后续面部表情制作。

这段文字是制作要求，不代表任何服务的专用字段或已验证功能。由操作者依实际工具支持的输入方式使用，并保存原始输出与制作记录。

## 制作流程与检查点

1. **生成静态网格。** 保存未经修整的原始模型和贴图，先查看正面、四分之三与侧面轮廓。若身份、脸型或发型明显偏离，重新选择生成结果；不要用材质或灯光掩盖结构问题。
2. **修整与重新拓扑。** 检查眼眶、上下眼睑、唇缘、嘴角、鼻翼和脸颊的连续性。需要变形的位置应有合理面流；扫描式碎面、薄膜、融合的眼球与眼睑应修复或重新拓扑。眼球、发型和服装保持可控的独立结构，清理内部不可见面、悬浮碎片、重复面和错误法线。
3. **处理头发、颈部与衣服。** 检查侧面和背面的头型完整性，重新组织必要的发束与发际线；头发不能依靠正面贴图遮住破洞。颈部与下颌衔接自然，衣领、拉链或门襟、T 恤的层级清晰，转头后也不穿插。
4. **完成 UV 与 PBR 贴图。** 提供 base color、roughness、normal；按需提供 AO、metallic。皮肤和布料不含烘死的强光、高光或阴影；眼睛有可读的虹膜、瞳孔与反光层次。普通皮肤、发丝与布料以非金属为主。验证 glTF 通道、法线方向和颜色空间，避免转换后肤色偏灰、过曝或眼睛变黑。
5. **制作面部绑定。** 在修整后的最终拓扑上制作下述表情目标，再导出并检查 GLB。静态网格生成成功不等于已经获得表情绑定，不假定图生服务自带可用的 face rig。
6. **优化、导出与网页验收。** 保留可编辑源文件，另导出网页用 GLB；先在独立检查页验证，再接入主页。未通过验收前不替换公开页面的角色或封面。

## 面部绑定最低交付

采用 glTF 可读取的 morph targets / Blender shape keys，至少提供以下 7 个语义控制。工具中的实际名称可以不同，但必须随模型提供名称映射、所在 mesh、默认值与有效范围；左右按人物自身方向定义。

| 语义控制 | 最低要求 |
| --- | --- |
| `blinkLeft`、`blinkRight` | 左右眼可独立闭合；上下眼睑自然接触并包覆眼球，不露白、不穿过眼球、不把眼睛缩成线条贴片 |
| `smileLeft`、`smileRight` | 左右嘴角可独立抬起，带动同侧脸颊，双侧组合形成自然微笑；唇线、鼻唇区和眼周随表情合理变化 |
| `browInnerUp` | 内眉自然上抬，额头与眉弓形体随之变化，不只是两条眉毛悬空移动 |
| `browOuterUpLeft`、`browOuterUpRight` | 左右外眉可独立抬起，眉毛贴合皮肤，眼睑和额头不过度拉伸 |

中性值应为 0，约定有效范围优先为 0–1。若实际使用其他范围，在映射中明确说明。眼球视线可通过独立眼球节点控制，转头可通过颈部/头部骨骼或稳定的头部父节点控制；不要用转动整张脸的方式替代表情。

所有 morph 必须作用于正确的最终网格，顶点数量与顺序一致；改变权重后应看到真实顶点变形。检查导出后的 glTF morph targets、初始 weights 和 JavaScript 可访问的名称映射，不能只在 Blender 中留下控制面板、驱动器或未烘焙的约束。若源资产只提供面部骨骼控制，由制作方转换为这里约定的可用 morph；转换能力需要实际验证。

分别测试每个目标的 0、0.5、1，并测试微笑、眨眼、抬眉的组合。目标不能造成眼睑穿眼球、嘴唇互穿、嘴角裂开、眉毛脱离皮肤或面部凹陷。不得交付无效的空 morph，或只靠改材质模拟表情。

## 网页资产预算

- 优先控制在约 **10 万三角形以内**、最终 **GLB 小于 5 MB**。这两个数字是优化目标，不是以牺牲脸部造型和表情为代价的硬性指标；超出时说明三角形、贴图与 morph 分别占用的成本，并实测加载与手机表现。
- 减面优先处理衣服背面、不可见内部结构和过密头发；保留眼睑、嘴角、脸颊等变形区域所需面数，所有 morph 同步经过同一拓扑处理。
- 贴图按实际屏幕占用选择分辨率，通常从 1K–2K 评估；复用贴图、合理打包材质，避免大量材质和独立小发束造成过多 draw calls。透明发卡须检查排序和移动设备成本。
- GLB 自包含贴图，无远程材质 URL 或运行时账号依赖。需要压缩时，确认当前网页已具备相应 decoder；保留未压缩母版，并验证压缩后 morph 和法线不变形。
- 记录导出坐标轴、单位、模型正面方向、头部与眼球节点名称及包围盒，便于稳定接入现有场景。

## 验收与交付

使用同一镜头、同一中性灯光和同一实际模型，提供以下可比较画面，并在浏览器里复现：

| 状态 | 验收重点 |
| --- | --- |
| 正面中性、四分之三中性 | 保持参考人物身份；嘴部放松、目光自然，脸、发际线和肩颈没有正面遮掩的结构问题 |
| 轻微微笑与较明显微笑 | 嘴角与脸颊一起变化，左右组合自然，嘴唇没有拉裂或穿插 |
| 左眼、右眼、双眼眨眼 | 可独立闭合；停在闭眼状态检查眼睑接触与眼球覆盖，再检查连续开合过程 |
| 头部左右各约 20° | 颈部衔接、耳朵、发型和衣领结构正常；眼球、眉毛、头发随头部正确运动 |
| 微笑同时眨眼并转头 | 组合权重有效，无穿插、法线跳变或绑定漂移 |

交付网页 GLB、可编辑建模源文件、PBR 源贴图、morph/节点映射、资产来源与授权记录，以及上述验收图和短预览。记录模型大小、三角形数、材质数、贴图尺寸、morph 数量和实际网页验证结果。若使用第三方资产，明确模型本身及纹理的公开网页分发权限，不能把工具或示例代码的 MIT/GPL 许可当作角色资产授权。

通过验收后，从**同一实际最终模型**渲染人物 fallback 和社交分享图，再同步替换网页资产；不以概念图冒充最终网格效果。真实手机的加载、表情播放和功耗表现仍需设备验证。所有未完成项保留为待办，不能仅凭生成成功或一张漂亮渲染图宣布角色已完成。
